# 接回上游 #42：服务归属和资源统计

来源：[上游 PR #42](https://github.com/tomjohndesign/what-the-port/pull/42)，提交 `3409ac187eac2018ad1f69d5b88dbe2f4f449fef`。

## 验收合同

- 同一启动器下的独立服务分别计算资源；停止一个服务不能停止另一个。
- 一个进程监听多个端口时，各行保留该服务的完整使用量，总内存和 CPU 去重，内存条按端口分摊。
- 停止一个共享进程会关闭它的所有监听端口。
- 隐藏端口也参与归属判断；PID 被重用后不继承旧 CPU 和历史。
- 保留本地 `libproc` 扫描、Homebrew 服务名称和保护策略、应用内存页、中文资源及已有截图修改。不整合其他上游更新。

## 实现和取舍

移植上游的 ProcessTree 和 ServerResources，用它们分别定义进程归属和共享资源统计。SocketScanner 保留直接读取 libproc，只增加所有监听者的索引，没有退回 lsof 子进程扫描。原生 UI、TUI、网站演示使用一致的资源统计边界。

保留本地版本化解释器和 Xcode Python 支持，同时采用上游对标准 Python framework 包装器的严格排除规则，避免把其他应用内嵌后端当成开发服务。修复自定义白名单只包含 python3 时漏掉 python3.14 的边界。

## 证据

- 同一组真实 Node 服务：旧安装版每个端口都包含启动器、两个服务及其他子进程；新构建只包含所属工作进程。证据：`.context/upstream-42/live-comparison.json`。
- 真实扫描和 ProcessControl.stop：停止单端口服务后，共享两端口的另一服务仍在；停止共享服务后，它的两个端口都消失。测试只在确认目标 PID 完全属于临时 fixture 后发送信号。
- Swift 完整测试通过，覆盖兄弟服务隔离、隐藏监听者、共享 socket workers、CPU 去重、PID 重用、重启命令、嵌套服务、原有中文资源和 Homebrew 过滤行为。
- `npm run test:resources`、`npm run build` 通过。
- 中文应用包构建、签名校验通过，版本 2.5.1 (11)，保持独立标识和禁用上游更新器。新版包直接运行 CLI 和中文 snapshot，Homebrew 服务名称和原生界面显示正常。
- Chrome 桌面演示验证列表、清理（5 行→3 行，总量 4.8 GB→4.6 GB）、服务详情和控制台；控制台无错误或警告。截图保存在 `.context/upstream-42/`。
- 网站示例服务独立，因此现有公开产品图片的布局和数值保持适用；没有替换其他图片。
