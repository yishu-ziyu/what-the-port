# 本地构建完成，但用户仍在运行旧版

2026-09-28 的截图功能已在源码中实现、构建，并通过隔离实例的快捷键与剪贴板验证；当时 `/Applications/WhatThePort 中文版.app` 仍是旧二进制。用户要的是用上功能，因此那次交付没有完成。两份不同的二进制都显示 `2.5.1 (10)`，版本号也掩盖了差异。

原因是把 [`build-localized.sh`](../../WhatThePort/build-localized.sh) 生成的 `.build/WhatThePort.app` 验证当成了已安装应用的验收。本项目的本机交付必须确认三个对象指向同一份新版：构建产物、`/Applications/WhatThePort 中文版.app`、正在运行的进程。完成替换和启动后，还要从**安装版**走一次功能入口，核对实际结果；构建、测试和隔离实例成功只证明各自对应的产物。

本次经用户明确要求后，已退出旧进程、替换安装包，核对安装版与新构建的可执行文件 SHA-256 相同，在真实设置窗口看到截图开关开启，并确认安装版的 ⌘X 启动了系统截图。`/Applications` 最终只留新版；用户要求不保留旧版后，旧包压缩备份也已移除。

后续交付功能不同的 App 时，应更新 [`build-localized.sh`](../../WhatThePort/build-localized.sh) 的 `WTP_BUILD`，避免相同版本号指向不同二进制。**当前这次本地构建仍标为 `2.5.1 (10)`，构建号尚未修正。**
